# Claude platform enablers for a lean idea-triage skill pack (state as of 21 October 2026)

Scope: research hand-offs (claude.ai Research, Claude Code `/deep-research`, a deep-research skill), skill-to-skill deferral, and moving files from a claude.ai chat Project into a GitHub repository. Each line cites a page opened in this run. Most help-center pages give only a relative "Updated …" stamp, which I convert against the run date of 2026-10-21. Quotes come from WebFetch extractions and are kept under 15 words.

## 1. Can a skill start Claude's Research mode in claude.ai? What does a Research report contain, and can it be saved into a Project?

### Takeaway
No documented mechanism lets a skill turn Research on. The user turns it on for each chat, from the "+" menu, and it needs web search on and a paid plan. Anthropic's current help article says nothing about the report's format or about saving it to a Project. User reports say reports land in the artifacts sidebar and download as `.md`. Claude cannot write into a chat Project's files, so the user has to download the report and re-upload it.

### Cited Findings
- The user turns Research on per chat: click "+" at the bottom left of the chat box, then "Research". A blue indicator shows it is on, and clicking it again turns it off. — [Use research on Claude, support.claude.com (undated; "Updated over a week ago" on 2026-10-21)](https://support.claude.com/en/articles/11088861)
- Web search must be on for Research to work. — [Use research on Claude, support.claude.com (undated)](https://support.claude.com/en/articles/11088861)
- Research is limited to paid plans (Pro, Max, Team, Enterprise), on the web, Claude Desktop and Claude Mobile. — [Use research on Claude, support.claude.com (undated)](https://support.claude.com/en/articles/11088861)
- Research runs on Claude Opus 5.5, falling back to Opus 4.8, whatever model the chat has selected. On Team/Enterprise it fails if an admin has disabled both models for the user's role. — [Use research on Claude, support.claude.com (undated)](https://support.claude.com/en/articles/11088861)
- Research searches the web plus the connectors enabled for the chat (for example Google Workspace), and it calls connector tools automatically without asking for approval each time. — [Use research on Claude, support.claude.com (undated)](https://support.claude.com/en/articles/11088861)
- The custom-connectors article separately confirms that Claude can call connector tools during Research without further approval. — [Custom connectors using remote MCP, support.claude.com (undated; "Updated over 2 weeks ago")](https://support.claude.com/en/articles/11175166)
- Limits: on Mobile, Research searches only the web and skips connectors. It cannot use local MCP servers configured in Claude Desktop. It draws on the same usage limits as normal chats but uses them up faster. — [Use research on Claude, support.claude.com (undated)](https://support.claude.com/en/articles/11088861)
- The troubleshooting advice for when Claude isn't researching is to prompt "Claude, please use the research tool to…". This implies that, once the toggle is on, Research is a tool the model chooses to call. — [Use research on Claude, support.claude.com (undated)](https://support.claude.com/en/articles/11088861)
- The current help article does not mention Projects, project knowledge, the report's format, citations, artifacts, run duration, Claude Code or skills. — [Use research on Claude, support.claude.com (undated)](https://support.claude.com/en/articles/11088861)
- Older behaviour: at launch on 15 April 2025, Research was an early beta for Max, Team and Enterprise in the US, Japan and Brazil only. It was turned on by toggling a "Research setting in chat" and returned answers "in minutes" with "easy-to-check citations". — [Claude blog: Research announcement (2025-04-15)](https://claude.com/blog/research)
- Conflict over time: the 2025 post describes a Research toggle and Max/Team/Enterprise availability. The current article describes a "+" menu item and adds Pro. Treat the 2025 post as superseded. — [Claude blog (2025-04-15)](https://claude.com/blog/research); [Use research on Claude (current)](https://support.claude.com/en/articles/11088861)
- One user reports that Deep Research reports appear in claude.ai's "Your creations" artifacts sidebar. Downloading one outside its project produces a generic `artifact-<hash>.md` filename instead of the report title, and characters in titles are not sanitized. — [GitHub issue anthropics/claude-code#28161 (opened 2026-02-24; closed "not planned" by bot 2026-03-24; no Anthropic reply)](https://github.com/anthropics/claude-code/issues/28161)
- The same report says one "Code Execution and File Creation" toggle controls Deep Research processing, file generation and interactive artifacts together. — [anthropics/claude-code#28161 (2026-02-24)](https://github.com/anthropics/claude-code/issues/28161)
- The same report says files in a claude.ai Project are read-only to Claude (it cannot write, update or delete them) and form a flat list with no folders. — [anthropics/claude-code#28161 (2026-02-24)](https://github.com/anthropics/claude-code/issues/28161)
- The documented way to add project knowledge is for the user to click "+" and upload documents, text files or code snippets. The article does not mention saving chat outputs or artifacts into the project. — [How can I create and manage projects?, support.claude.com (undated; "Updated over a week ago")](https://support.claude.com/en/articles/9519177-how-can-i-create-and-manage-projects)
- New in 2026: redesigned Projects include a library that "collects the files you add and the artifacts produced by Claude". This exists only in a Claude Code beta. Existing chat Projects "keep working as they do today". — [Projects redesigned: from folder to conversation, claude.com (2026-09-17)](https://claude.com/resources/articles/projects-redesigned)
- Third-party claim (not Anthropic): the Research toggle exists only in the claude.ai web interface, with no `/research` command or API endpoint. The workaround runs `claude --chrome` so a background agent clicks the toggle, polls until the report finishes (5–30 minutes) and saves Markdown under `./docs/research/`. — [How to Use Claude.ai's Research Toggle Inside Claude Code, DEV Community, Bilal Haidar (posted "Jan 27", year likely 2026)](https://dev.to/bhaidar/how-to-use-claudeais-research-toggle-inside-claude-code-469d)

### Inferences
- A skill cannot start Research. The most it can do is tell the user to switch Research on (and web search, if it is off), then give them a ready-made research question. Once the toggle is on, the "use the research tool" phrasing suggests the skill's instructions could steer Claude towards Research, but no Anthropic page confirms that a skill can call it.
- Research always runs on Opus 5.5/4.8, uses up limits faster and calls connectors without approval. A lean triage pack should present it as an optional, user-started deep dive, not something that runs automatically.
- To get a Research report into a chat Project's knowledge, the user has to download it (as `.md` according to #28161) and upload it again. I found no documented "save to project" action. The automatic library collection exists only in the redesigned Projects beta, and nothing says it covers Research reports.
- #28161 refers to downloading a report "outside its project", which suggests Research can run inside Project chats. No Anthropic page confirms this.

### Gaps
- No Anthropic page I opened describes what a Research report looks like on screen (sections, citation style, inline or footnote) or its export options (Markdown, PDF, copy). The only evidence is the 2025 "easy-to-check citations" line and the user report in #28161.
- I could not confirm from an opened page whether Research inside a Project reads project knowledge.
- Run duration: a "45 minutes" figure (attributed to Ars Technica) appeared only in a search snippet, so it is unverified. The dev.to post says 5–30 minutes, and the current help article gives no figure.
- Searches behind "a skill cannot start Research" and "no save-to-project path": WebSearch "Claude Research mode help article"; "support.claude.com research report citations artifact save to project"; "Claude Research report format citations download PDF markdown project"; "claude.ai "add to project" artifact project knowledge save"; "Claude skill trigger Research mode automatically without toggle". Pages fetched: support.claude.com 11088861, 9519177, 12512180, 11175166; claude.com/blog/research; claude.com projects-redesigned. None describes a programmatic way to start Research or a save-to-project action for Research output. A third-party guide (only in a search snippet, not opened) said artifacts could be saved to projects, and it was about two years old.

## 2. How does Claude Code's /deep-research workflow, or a deep-research skill, accept a brief, what does it output and where, and what does it cost or warn about?

### Takeaway
Claude Code's bundled `/deep-research <question>` takes a free-text question. Since v2.1.218 only the user can start it, and it asks for approval before running. It runs in the background on dozens of subagents, cross-checks claims and posts one cited report into the session. The docs describe no report file, only the orchestration script under `~/.claude/projects/`. The separate `anthropic-skills:deep-research` skill takes a natural-language request and writes Markdown files into the working directory: `research_notes/{title}/*.md` plus `reports/{title}.md`. Both bill against plan usage, and the workflow shows a "Large workflow" warning above 25 agents or 1.5M tokens.

### Cited Findings
- `/deep-research <question>` is Claude Code's bundled dynamic workflow. It fans out web searches across several angles, fetches and cross-checks sources, votes on each claim and returns a cited report with failed claims removed. It requires the WebSearch tool. — [Orchestrate subagents at scale with dynamic workflows, code.claude.com (undated)](https://code.claude.com/docs/en/workflows)
- Input is the free-text question after the command. The docs' example asks about Node.js permission-model changes between v20 and v22. — [Dynamic workflows, code.claude.com (undated)](https://code.claude.com/docs/en/workflows)
- Saved (user-authored) workflows accept structured input through an `args` global, for example a research question or a list of paths. — [Dynamic workflows, code.claude.com (undated)](https://code.claude.com/docs/en/workflows)
- `/deep-research` runs only when the user invokes it. Before v2.1.218 Claude could also start it on its own. — [Commands, code.claude.com (undated)](https://code.claude.com/docs/en/commands)
- Approval in the CLI: a prompt lists the planned phases with "Yes, run it", "Yes, and don't ask again" (for named workflows), "View raw script" and "No". Auto mode asks only on first launch. Manual and accept-edits modes ask every run. Bypass mode never asks. In `-p` and the SDK there is no prompt, but permission rules apply, so `Workflow` or `Workflow(<name>)` allow rules are needed. — [Dynamic workflows, code.claude.com (undated)](https://code.claude.com/docs/en/workflows)
- In the Desktop app, an approval card shows the workflow name, the phase list and a token-usage caution, with Once, Always and Deny buttons. — [Dynamic workflows, code.claude.com (undated)](https://code.claude.com/docs/en/workflows)
- Output: the run is watched from `/workflows`, and when it finishes "the report appears in your session" with per-claim source citations. Claims the verifiers could not check (for example after a rate limit) are listed as unverified, not refuted. — [Dynamic workflows, code.claude.com (undated)](https://code.claude.com/docs/en/workflows)
- Where files go: every run writes its script to a file under the session's directory in `~/.claude/projects/`, and saved results allow a resume. The page does not describe writing the report itself to a file. — [Dynamic workflows, code.claude.com (undated)](https://code.claude.com/docs/en/workflows)
- Plans: dynamic workflows are available on all paid plans, the Anthropic API, Amazon Bedrock, Google Cloud's Agent Platform and Microsoft Foundry. On Pro they must be switched on in `/config`. — [Dynamic workflows, code.claude.com (undated)](https://code.claude.com/docs/en/workflows)
- Workflows can be turned off with the `/config` toggle, the `disableWorkflows` setting, the `CLAUDE_CODE_DISABLE_WORKFLOWS=1` environment variable or managed settings. When they are off, the workflow commands are unavailable. — [Dynamic workflows, code.claude.com (undated)](https://code.claude.com/docs/en/workflows)
- Cost: a run "can use meaningfully more tokens" than doing the work in conversation and counts toward usage and rate limits. A "Large workflow" warning appears above 25 scheduled agents or a projected 1.5M tokens. The warning is advisory and does not pause the run. — [Dynamic workflows, code.claude.com (undated)](https://code.claude.com/docs/en/workflows)
- Size guideline: the default is `medium` (under 10 agents), or `small` (under 5) on Pro with v2.1.271+. The setting needs v2.1.219+, and earlier versions default to unrestricted. — [Dynamic workflows, code.claude.com (undated)](https://code.claude.com/docs/en/workflows)
- Hard limits: no user input mid-run, up to 16 concurrent agents by default, 4,096 items per `parallel()`/`pipeline()` call and 1,000 agents per run. — [Dynamic workflows, code.claude.com (undated)](https://code.claude.com/docs/en/workflows)
- Usage limits: from v2.1.271, a run that hits a claude.ai usage limit pauses instead of failing. This only happens in interactive subscription sessions with `autoContinueAtUsageLimit` on, a reset within 24 hours, and at most two waits. Otherwise the affected agents fail. — [Dynamic workflows, code.claude.com (undated)](https://code.claude.com/docs/en/workflows)
- The `ultracode` keyword counts as opting in to a workflow only in a prompt the user types. It does not start a workflow from `-p`, unstamped SDK input, scheduled tasks, webhooks or PR comments. — [Dynamic workflows, code.claude.com (undated)](https://code.claude.com/docs/en/workflows)
- The `anthropic-skills:deep-research` skill (a separate thing, synced into this session) should be used when a request needs multi-source research plus a narrative report. It should be used only when an Agent/Task tool can spawn subagents, and otherwise Claude should research directly. — [deep-research SKILL.md, local copy at /Users/ramboz/.claude/local-agent-mode-sessions/skills-plugin/55ffbe58-9102-4be8-be99-6089bbad141c/2468e27a-1eff-46c8-8f73-8381c17f877d/skills/deep-research/SKILL.md (file modified 2026-10-09)](file:///Users/ramboz/.claude/local-agent-mode-sessions/skills-plugin/55ffbe58-9102-4be8-be99-6089bbad141c/2468e27a-1eff-46c8-8f73-8381c17f877d/skills/deep-research/SKILL.md)

### Inferences
- A triage skill in Claude Code cannot start `/deep-research` itself, because it has been user-only since v2.1.218. It has to hand the user a ready-to-paste `/deep-research <question>` line. The bundled workflow takes a question, not a structured brief, so the brief has to be packed into that one line.
- The workflow's report lives only in the session transcript, so any triage step that needs it as a file needs the user, or a follow-up turn, to save it. The skill variant writes files, but into `cwd`. In a repo that means `research_notes/` and `reports/` at whatever directory the session started in.
- The skill's frontmatter has only `name` and `description` (no `disable-model-invocation`), so it is model-invocable. Another skill could in principle defer to it, subject to the nested-skill bugs in Question 3. Its own guard means it only works where an Agent/Task tool exists, which rules out plain claude.ai chat.
- A triage skill can mirror the skill's brief shape (Objective / Key questions / Suggested sources / Constraints) when handing off, so the deep-research skill or the user can reuse it unchanged.

### Gaps
- I did not find the official changelog entry that introduced `/deep-research`. One third-party snippet (not opened) claimed workflows started as a research preview needing v2.1.154+, so that is unverified.
- The `/deep-research` report's internal structure (sections, citation style) is not documented beyond "cited report".
- I could not confirm whether `anthropic-skills:deep-research` is also available in claude.ai chat or only in Claude Desktop, Cowork and Claude Code. The local copy has no date or version.
- Neither the workflow docs nor the skill give a per-run token or dollar estimate.
- Searches behind "no report file is documented": I fetched code.claude.com workflows and commands. WebSearch: ""deep-research" Claude Code workflow command docs"; "Claude Code changelog "/deep-research" workflow added version". None describes a report file path.

## 3. Can one skill invoke or defer to another installed skill, in claude.ai and in Claude Code? What do Anthropic's docs say about composition, skills calling skills, and selection reliability?

### Takeaway
Anthropic's marketing and overview pages call skills "composable", but no Anthropic doc defines a skill-calls-skill mechanism on any surface. In Claude Code, nested `Skill()` calls do happen, but they break in documented ways. `disable-model-invocation` blocks delegated calls (open request #86763, August 2026). The parent skill's flow ends when the child finishes (open bug #17351, January 2026). Skill selection depends on descriptions that can be truncated or dropped when many skills are installed. In claude.ai, selection is automatic, and the only lever is naming the skill in the request.

### Cited Findings
- In Claude Code, Claude uses skills "when relevant", or the user types `/skill-name`. — [Extend Claude with skills, code.claude.com (undated)](https://code.claude.com/docs/en/skills)
- With `disable-model-invocation: true`, Claude cannot invoke the skill on its own, "Claude Code blocks the call" and the description is left out of context. With `user-invocable: false`, only Claude can invoke it. — [Extend Claude with skills, code.claude.com (undated)](https://code.claude.com/docs/en/skills)
- A skill name typed mid-message ("go ahead and /deploy to staging") counts as the user's permission for that message, so Claude can run the skill while responding. — [Extend Claude with skills, code.claude.com (undated)](https://code.claude.com/docs/en/skills)
- Users can stack skills at the terminal prompt: `/write-tests /fix-issue 123` loads both. Through the Agent SDK or `claude -p`, only the first loads. — [Extend Claude with skills, code.claude.com (undated)](https://code.claude.com/docs/en/skills)
- Up to six skills can be chained at the start of one message. — [Commands, code.claude.com (undated)](https://code.claude.com/docs/en/commands)
- Skill access is controlled by permission rules: denying `Skill` blocks all skills, `Skill(commit)` is an exact match and `Skill(deploy *)` a prefix match. Deny rules also block nested, aliased and synced variants. Before v2.1.260, an unqualified deny did not block a nested skill listed under its qualified name. — [Extend Claude with skills, code.claude.com (undated)](https://code.claude.com/docs/en/skills)
- The Claude Code skills page describes no mechanism for one skill to call another. Users stacking skills is the only composition it documents. — [Extend Claude with skills, code.claude.com (undated)](https://code.claude.com/docs/en/skills)
- `context: fork` runs a skill in a subagent that "doesn't see your conversation history", in the background by default (`background: false` waits for it). It only makes sense for skills with explicit task instructions. — [Extend Claude with skills, code.claude.com (undated)](https://code.claude.com/docs/en/skills)
- Open feature request: `disable-model-invocation` blocks both proactive and delegated (parent-skill) invocation, so a child skill cannot be callable by its parent while hidden from proactive routing. Telemetry already distinguishes `user-slash`, `claude-proactive` and `nested-skill` origins. Anthropic staff have not replied. — [anthropics/claude-code#86763 (opened 2026-08-14; open; labels area:skills, enhancement)](https://github.com/anthropics/claude-code/issues/86763)
- #86763 rejects having the parent read the child's SKILL.md instead, because that drops arguments, tool policy, model, forked context and hooks. A commenter (2026-10-09) contrasts Codex's `allow_implicit_invocation: false`. — [anthropics/claude-code#86763 (2026-08-14)](https://github.com/anthropics/claude-code/issues/86763)
- Related issues, as listed on #86763's page (I did not open them): #79560, a regression where the built-in `/code-review` rejects invocation from another skill (shown open); #56912, where `Skill()` entries in `allowed-tools` are ignored so nested calls still prompt; #43809, closed for inactivity. — [anthropics/claude-code#86763 (2026-08-14)](https://github.com/anthropics/claude-code/issues/86763)
- Open bug: when a skill invokes another with `Skill(...)`, control returns to the main session rather than to the parent, and the parent's workflow stops. This happens with and without `context: fork`. It has been reproduced on v2.1.3, 2.1.9, 2.1.37 and Windows, with no Anthropic response. — [anthropics/claude-code#17351 (opened 2026-01-10; open; labels bug, area:core, has repro)](https://github.com/anthropics/claude-code/issues/17351)
- A workaround posted on #17351 (2026-05-20) told the model to Read the child SKILL.md and run it inline instead of calling `Skill()`. It was unreliable: the model still sometimes called `Skill()`, and the bug recurred in production four days later. — [anthropics/claude-code#17351](https://github.com/anthropics/claude-code/issues/17351)
- Conflict: a #17351 commenter reports that a prompt with `/skill1` then `/skill2` stops after skill1. The docs say stacked skills at the terminal prompt both load. The two claims may describe different syntax and versions. — [anthropics/claude-code#17351](https://github.com/anthropics/claude-code/issues/17351); [Extend Claude with skills](https://code.claude.com/docs/en/skills)
- Selection mechanics: the skill listing always includes every name, but descriptions are dropped to fit a budget of 1% of the context window, least-invoked skills first. Each entry is capped at 1,536 characters for `description` + `when_to_use`. The budget can be changed with `skillListingBudgetFraction`, `SLASH_COMMAND_TOOL_CHAR_BUDGET` or `skillListingMaxDescChars`. — [Extend Claude with skills, code.claude.com (undated)](https://code.claude.com/docs/en/skills)
- If a skill doesn't trigger: put natural keywords in the description, check "What skills are available?", rephrase, or invoke it directly. Malformed YAML loads the body with empty metadata, so Claude cannot match the description. — [Extend Claude with skills, code.claude.com (undated)](https://code.claude.com/docs/en/skills)
- Reliability: the docs say "Seeing a skill trigger tells you Claude found it". The tools offered are `/skill-doctor` (finds listed but never-invoked skills), `claude plugin eval` with a `tool_used: Skill` grader, and skill-creator's description tuning. — [Extend Claude with skills, code.claude.com (undated)](https://code.claude.com/docs/en/skills)
- When Claude stops following a skill, the advice is to move must-hold rules into hooks, because skill content is not re-read on later turns. After compaction, only the first 5,000 tokens of each invoked skill are re-attached, within a combined 25,000-token budget. — [Extend Claude with skills, code.claude.com (undated)](https://code.claude.com/docs/en/skills)
- Cross-surface guidance: the description decides selection, "potentially 100+ available Skills" may compete, and descriptions should be written in third person. `name` is limited to 64 characters and `description` to 1,024. References should stay one level deep, because Claude may only `head -100` nested files. Skills should be tested on Haiku, Sonnet and Opus. — [Skill authoring best practices, platform.claude.com (undated)](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- Conflict: the platform best-practices page says "There is not currently a built-in way to run these evaluations". Claude Code documents `claude plugin eval` for plugin skills. The two may differ only because they cover different surfaces. — [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices); [Extend Claude with skills](https://code.claude.com/docs/en/skills)
- The overview lists "Compose capabilities: Combine Skills for complex, multistep tasks". Metadata costs about 100 tokens per skill, and a loaded SKILL.md body stays under 5k tokens. — [Agent Skills overview, platform.claude.com (undated)](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview)
- The launch post (2025-10-16) says "Skills stack together", with Claude identifying the skills a task needs and coordinating them, but gives no mechanism. ### Inferences
- Treat "defer to another skill" as a soft hand-off: describe when the other skill fits and let Claude, or the user, pick it. Do not rely on a hard `Skill()` call. In Claude Code, a nested call may end the parent's flow (#17351), so put any child call last and state the next step in plain text in case control does not come back.
- A child skill that a parent should call must stay model-invocable (no `disable-model-invocation`), which also exposes it to proactive routing (#86763). A user-only child, such as `/deep-research`, can only be reached by asking the user to type it.
- With many skills installed, a lean pack's descriptions should put the trigger phrases first and stay well under 1,536 characters (or 1,024 for claude.ai/API portability). Overflowed descriptions are dropped for the least-used skills first, which is exactly where a new pack starts.
- Because claude.ai skills now sync into Claude Code, a pack uploaded once to claude.ai can reach both surfaces for signed-in users. Behaviour still differs (no slash invocation in claude.ai chat, no Agent tool there), and the platform overview page is stale on this point.

## 4. What changed in 2026 about moving files from a claude.ai chat Project into a GitHub repository (Projects redesign, GitHub integration, export, artifacts)?

### Takeaway
As of October 2026, no first-party path moves files from a claude.ai chat Project into a GitHub repo. The GitHub integration only reads, from repo into private Projects. Claude cannot write project files. The account export does not mention projects. The 17 September 2026 Projects redesign adds threads that open PRs and a library of files and artifacts, but only as a Claude Code beta for some Pro/Max users. Existing chat Projects are unchanged, with no date for their upgrade. Moving files today means the user downloads and commits them, or works in Claude Code. A custom GitHub MCP connector might allow writes from chat, but I did not verify this.

### Cited Findings
- The claude.ai GitHub integration reads file names, file contents and branch content. It does not read commit history, PRs, issues or repo metadata. For editing code or opening PRs it points to Claude Code. — [GitHub integration, claude.com/docs (undated)](https://claude.com/docs/connectors/github)
- The integration is available on every plan, including Free, and covers public repos and private repos the user has granted access to. — [GitHub integration, claude.com/docs (undated)](https://claude.com/docs/connectors/github)
- Repo content can only be added to a private (unshared) project. In shared projects the option is greyed out with "Only accessible from private projects". — [GitHub integration, claude.com/docs (undated)](https://claude.com/docs/connectors/github)
- Repo content is refreshed with "Sync now", the selected content must fit the context window, and losing repo access removes the preview but keeps the conversation history. — [GitHub integration, claude.com/docs (undated)](https://claude.com/docs/connectors/github); [Use the GitHub integration, support.claude.com ("Updated yesterday" on 2026-10-21)](https://support.claude.com/en/articles/10167454-use-the-github-integration)
- The support article only describes syncing files from a branch. It says Anthropic does "not retrieve commit history, PRs, or other metadata", does not mention writing or exporting to GitHub, and gives no plan information. — [Use the GitHub integration, support.claude.com (~2026-10-20)](https://support.claude.com/en/articles/10167454-use-the-github-integration)
- On Team and Enterprise, the GitHub Integration appears only while GitHub is turned on for the organization. — [GitHub integration, claude.com/docs (undated)](https://claude.com/docs/connectors/github)
- Projects redesign (2026-09-17): a coordinator scopes the work and hands it to worker threads, each a "Claude Code cloud session" on "its own branch and copy of the repo". With repositories connected, "a thread opens pull requests and runs your tests". — [Projects redesigned: from folder to conversation, claude.com (2026-09-17)](https://claude.com/resources/articles/projects-redesigned)
- Redesign availability: a beta in Claude Code for select Pro and Max subscribers who use cloud sessions and have no existing web or desktop projects, expanding "over the coming week". Team and Enterprise come later, and there is a waitlist. — [Projects redesigned, claude.com (2026-09-17)](https://claude.com/resources/articles/projects-redesigned)
- Existing chat Projects "keep working as they do today" and will be upgraded "as the rollout expands to chat and Cowork". No date is given. — [Projects redesigned, claude.com (2026-09-17)](https://claude.com/resources/articles/projects-redesigned)
- Redesigned Projects have a library of added files and Claude's artifacts, project-level usage reporting, and model and effort choices for the coordinator and workers. They "can reach usage limits faster", threads run only in the cloud, and local runs are "coming very soon". — [Projects redesigned, claude.com (2026-09-17)](https://claude.com/resources/articles/projects-redesigned)
