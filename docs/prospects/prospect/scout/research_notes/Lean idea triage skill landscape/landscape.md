# Lean idea triage skill landscape (as of 2026-10-21)

Scope: research-brief generators for deep-research tools ("draft then process"), standalone idea-triage / idea-validation skills, and grilling / pressure-test skills another skill could hand a plan to. Every source below was opened in this run on 2026-10-21. GitHub dates are commit dates from the GitHub API. "Installs" are the skills.sh counts shown on 2026-10-21; skills.sh does not say how it counts them (see Gaps). "claude.ai-installable" uses the caller's test: (a) a Git plugin marketplace (`.claude-plugin/marketplace.json`) with no top-level `bin/`, or (b) a single skill whose frontmatter uses only the fields the Agent Skills spec defines.

## Q1. Which tools turn an idea into a brief for a deep-research tool, then turn the finished report back into structured, cited evidence ("draft then process")?

### Takeaway
BMAD Deep Recon already does the full loop. Draft writes a prompt the user pastes into their own deep-research tool. Process files the returned report untouched, pulls every claim into per-claim digests (claim, source, publisher, pub_date, accessed, confidence), checks them against a research "pack", and writes a cited summary for downstream skills. It is part of the BMAD framework and needs `uv` plus BMAD's `_bmad/scripts`. Outside BMAD, only small, low-adoption skills cover either half: rohankgeorge/the-researcher (prompt builder plus a separate report-verification skill), kj-aiml and raymond-hear prompt generators, and web prompt generators. I found no idea-validation skill that delegates its research instead of running it.

### Cited Findings
**BMAD Deep Recon (framework skill: BMAD core / toolbox)**
- Deep Recon has three modes. Draft writes a research prompt you run in ChatGPT, Gemini, Grok or Perplexity. Process takes a finished report from any source and writes a cited summary. Run does the research in-session after one plan approval. — [Research a Decision, BMAD docs](https://docs.bmad-method.org/plan/research-a-decision/), undated (footer © 2026)
- The docs list Deep Recon's limits. Draft needs a manual round trip, and its quality depends on the outside tool. Process is only as good as the report supplied. Claims past their freshness window are reported as history. — [Research a Decision, BMAD docs](https://docs.bmad-method.org/plan/research-a-decision/), undated
- The SKILL.md calls Deep Recon "a research director, not a search engine". It names Draft, then running externally, then Process as "the natural loop". — [bmad-deep-recon/SKILL.md](https://github.com/bmad-code-org/BMAD-METHOD/blob/main/skills/bmad-deep-recon/SKILL.md), last commit 2026-10-17; earliest commit in path history 2026-08-20 (22 commits)
- For a bare research ask, Deep Recon offers Run here or Draft for the user's subscribed tool. It states the trade-off: tokens and minutes in-session versus one manual round trip. — [bmad-deep-recon/SKILL.md](https://github.com/bmad-code-org/BMAD-METHOD/blob/main/skills/bmad-deep-recon/SKILL.md), 2026-10-17
- Deep Recon has a "research firewall": project context shapes what to ask, but never counts as evidence. — [bmad-deep-recon/SKILL.md](https://github.com/bmad-code-org/BMAD-METHOD/blob/main/skills/bmad-deep-recon/SKILL.md), 2026-10-17
- Draft asks which tool the prompt is for and writes tool-neutral text if unknown. It embeds a citation demand (URL plus publication date, contrary evidence, admitted gaps). It structures the requested output so Process can extract it, saves `brief.md` in a run folder and tells the user to bring the report back. — [deep-recon references/draft.md](https://github.com/bmad-code-org/BMAD-METHOD/blob/main/skills/bmad-deep-recon/references/draft.md), 2026-10-17
- Process works in steps:
  - copies the original into `imports/` untouched and records provenance (which tool, when);
  - uses a fresh-context subagent to extract claims as `{claim, source, publisher, pub_date, accessed, confidence, class}`;
  - spot-checks load-bearing claims and lists open dimensions, each with a route (a follow-up Draft or a targeted Run);
  - writes the decision-first summary that downstream skills read.
  — [deep-recon references/process.md](https://github.com/bmad-code-org/BMAD-METHOD/blob/main/skills/bmad-deep-recon/references/process.md), 2026-10-17
- Deep Recon has six research types (market, domain, technical, competitive, user-voice, academic-lit). The v6 market, domain and technical research skills were merged into it. — [Research a Decision, BMAD docs](https://docs.bmad-method.org/plan/research-a-decision/), undated
- Dependency: on activation Deep Recon runs `uv run {project-root}/_bmad/scripts/resolve_customization.py`. If the script is missing, it offers to install and run BMAD setup (`npx skills add bmad-code-org/BMAD-METHOD --skill bmad`). — [bmad-deep-recon/SKILL.md](https://github.com/bmad-code-org/BMAD-METHOD/blob/main/skills/bmad-deep-recon/SKILL.md), 2026-10-17
- Deep Recon says Run needs web access. Without it, the skill offers Draft or Process. — [bmad-deep-recon/SKILL.md](https://github.com/bmad-code-org/BMAD-METHOD/blob/main/skills/bmad-deep-recon/SKILL.md), 2026-10-17
- BMAD ships on two lines. Stable v6.12 installs with `npx bmad-method install`. V7 is a "preview alpha" whose skills, install path and docs "change often". Both lines need `uv`. — [BMAD-METHOD README](https://github.com/bmad-code-org/BMAD-METHOD), main branch read 2026-10-21; latest release v6.12.4 dated 2026-10-14 ([releases](https://github.com/bmad-code-org/BMAD-METHOD/releases))

### Inferences
- "Write a brief, then turn the returned report into a cited evidence ledger" is not novel. BMAD Deep Recon implements both halves with more rigor (freshness windows, two-source classes, provenance). It is the strongest evidence against novelty for that part of the idea. Its weakness for this brief is packaging: it is tied to BMAD setup (`uv`, `_bmad/scripts`, project root) and sits on a V7 line whose own README calls it an unstable alpha.
- Outside BMAD, the closest lean pair is rohankgeorge/the-researcher (builder plus verification). It is not idea-specific, does not hand off to build tools, and has negligible adoption (2 stars, about 3 installs).
- The prompt-builder skills found stop at the brief. None I read includes a Process step that turns the returned report back into structured evidence for a later skill.

### Gaps
- I could not search OpenAI's GPT Store. Web searches ("deep research" prompt generator GPT ChatGPT; chatgpt.com/g deep research prompt builder GPT) surfaced no specific GPT, so GPT-packaged brief generators are unverified.

- I did not check whether Deep Recon's Process works in claude.ai chat without BMAD's scripts (its SKILL.md falls back to defaults only on "any other failure", not on a missing script).

## Q2. Which small, standalone idea-triage or idea-validation skills or plugins exist outside a framework, and which install into claude.ai chat?

### Takeaway
There are many small idea-validation skills. The most-installed are addyosmani `idea-refine` (55,762), slavingia `validate-idea` (2,966), builder-os `idea-validator` (1,691) and ailabs-393 `startup-validator` (1,539). Most are single SKILL.md files with spec-only frontmatter, so they meet the zip criterion for claude.ai. Several sit in plugin marketplaces without a top-level `bin/`. Almost all run their own web research and default to blunt or harsh verdicts. None delegates research to the user's research tool. The ones that hand off do so to siblings in their own pack.

### Cited Findings
**What makes something claude.ai-installable (Anthropic docs)**
- Plugins work in web chat, the Desktop Chat tab and Cowork. You add a GitHub marketplace via Customize > Plugins > Add > Add marketplace with owner/repo. A paid plan is required. — [Use plugins in Claude, Claude Help Center](https://support.claude.com/en/articles/13837440-use-plugins-in-claude), "Updated over 2 weeks ago" (no absolute date)
- In chat, sub-agents and hooks are grayed out and local MCP servers do not run. Skills and commands work everywhere. — [Use plugins in Claude](https://support.claude.com/en/articles/13837440-use-plugins-in-claude), undated
- A top-level `bin/` directory stops claude.ai and Cowork from installing a plugin at all. Agents and hooks are ignored in chat without an error. — [Plugin structure and testing, Claude docs](https://claude.com/docs/plugins/build), read 2026-10-21
- Without a `plugin.json`, Anthropic's directory lists a skills-only folder for Claude Code only, not for claude.ai or Cowork. — [Plugin structure and testing](https://claude.com/docs/plugins/build), read 2026-10-21
- A single skill is uploaded as a ZIP whose top level is the skill folder. Required frontmatter is `name` (≤64 chars, matching the folder) and `description` (≤1,024 chars). The page also says to keep SKILL.md under 500 lines. — [Create custom skills, Claude docs](https://claude.com/docs/skills/how-to), read 2026-10-21
- Conflict on description length: a third-party guide in search results claimed claude.ai limits descriptions to 200 characters. Anthropic's how-to page says up to 1,024 characters. — [Create custom skills](https://claude.com/docs/skills/how-to) vs search snippet (verdent.ai guide, not opened)
- The Agent Skills spec defines only these fields: `name`, `description`, `license`, `compatibility` (≤500 chars), `metadata` (string-to-string map) and `allowed-tools` (experimental, space-separated). — [Agent Skills Specification](https://agentskills.io/specification), undated
