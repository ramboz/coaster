# Nobody ships the idea-research loop lean yet

No small, framework-free pack does what this idea proposes, but its core loop already exists: BMAD's Deep Recon (first committed 2026-08-20) writes a brief for the user's own deep-research tool and turns the returned report into per-claim, dated, sourced evidence, and BMAD's Forge Idea pressure-tests ideas, both behind BMAD's `uv` and `_bmad/scripts` setup ([bmad-deep-recon SKILL.md, 2026-10-17](https://github.com/bmad-code-org/BMAD-METHOD/blob/main/skills/bmad-deep-recon/SKILL.md); [bmad-forge-idea SKILL.md, 2026-10-17](https://github.com/bmad-code-org/BMAD-METHOD/blob/main/skills/bmad-forge-idea/SKILL.md)). Outside BMAD there are only fragments: rohankgeorge/the-researcher pairs a brief builder with a report checker but has 3 installs and no build handoff, and mattpocock's standalone `grilling` (960,166 skills.sh installs, listed in Anthropic's official directory) is the obvious target for an optional challenge step. Dozens of small idea validators exist, yet almost all run their own web research and default to blunt verdicts; none delegates research, and none is encouraging by default with challenge only on request (the closest, gstack's Builder mode, is locked inside gstack and cannot install in claude.ai). The platform routes every hop through the user: no skill can start claude.ai Research or Claude Code's `/deep-research` (user-only since v2.1.218), Claude cannot write into a chat Project, the GitHub integration only reads, and the only Project-to-pull-request path is a Claude Code beta announced 2026-09-17. One skill calling another is undocumented and fragile, so the handoff to grilling has to be a soft, last-step suggestion. On reach, a June 2026 study found pass rates fell 8 to 21 points as skill libraries grew to 202 skills, which favors lean packs, but half of all skills are installed exactly once and a framework pack (Superpowers, about 1.0M installs) runs close behind Anthropic's own top plugin on claude.com. The opening is a gap in packaging and defaults, not in capability, and a new pack from a little-known author starts at the back of a very concentrated queue.

_Every source was opened on 2026-10-21. "Undated" marks pages with no publication date; help-center pages show only relative "Updated…" stamps. Install counts are skills.sh snapshots from 2026-10-21 unless stated otherwise._

## BMAD's Deep Recon already runs draft-then-process, but only inside BMAD

The full brief-then-ledger loop has shipped, inside BMAD. **Deep Recon has three modes.** Draft writes a research prompt the user runs in ChatGPT, Gemini, Grok or Perplexity. Process takes a finished report from any source and writes a cited summary. Run does the research in-session after one plan approval ([Research a Decision, BMAD docs, undated, © 2026](https://docs.bmad-method.org/plan/research-a-decision/)). The SKILL.md casts the skill as a research director rather than a search engine and calls Draft, then the outside run, then Process, its natural loop. For a bare research ask it offers Run or Draft and states the trade-off: tokens and minutes in-session, or one manual round trip ([bmad-deep-recon SKILL.md, 2026-10-17](https://github.com/bmad-code-org/BMAD-METHOD/blob/main/skills/bmad-deep-recon/SKILL.md)). Draft asks which tool the prompt is for and writes tool-neutral text if the user doesn't know. It embeds a citation demand (URL plus publication date, contrary evidence, admitted gaps). It shapes the requested output so Process can parse it, saves `brief.md` in a run folder and tells the user to bring the report back ([draft.md, 2026-10-17](https://github.com/bmad-code-org/BMAD-METHOD/blob/main/skills/bmad-deep-recon/references/draft.md)). Process **copies the original report untouched into `imports/` with provenance. A fresh-context subagent then extracts every claim as `{claim, source, publisher, pub_date, accessed, confidence, class}`.** Process spot-checks the load-bearing claims, lists open questions with a route for each (a follow-up Draft or a targeted Run), and writes a decision-first summary for downstream skills ([process.md, 2026-10-17](https://github.com/bmad-code-org/BMAD-METHOD/blob/main/skills/bmad-deep-recon/references/process.md)). A "research firewall" lets project context shape the questions but never count as evidence ([SKILL.md, 2026-10-17](https://github.com/bmad-code-org/BMAD-METHOD/blob/main/skills/bmad-deep-recon/SKILL.md)). Deep Recon covers six research types and replaced BMAD v6's separate market, domain and technical research skills ([Research a Decision, undated](https://docs.bmad-method.org/plan/research-a-decision/)). This is a cited evidence ledger in all but name. It goes further than the idea's own brief, with freshness windows, provenance and claim classes. It is the strongest evidence that the loop itself is not new.

**Its weak point is packaging, and it is new.** The skill's path history starts on 2026-08-20, with 22 commits by 2026-10-17 ([SKILL.md](https://github.com/bmad-code-org/BMAD-METHOD/blob/main/skills/bmad-deep-recon/SKILL.md)). On activation it runs `uv run {project-root}/_bmad/scripts/resolve_customization.py`. If the script is missing, it offers to run BMAD setup. Run mode needs web access; without it, the skill offers Draft or Process ([SKILL.md, 2026-10-17](https://github.com/bmad-code-org/BMAD-METHOD/blob/main/skills/bmad-deep-recon/SKILL.md)). BMAD ships stable v6.12.4 (2026-10-14) through `npx bmad-method install`. It also ships a V7 "preview alpha" whose skills and install path its own README says change often. Both lines need `uv` ([BMAD-METHOD README, read 2026-10-21](https://github.com/bmad-code-org/BMAD-METHOD); [releases, v6.12.4 2026-10-14](https://github.com/bmad-code-org/BMAD-METHOD/releases)). Deep Recon and Forge Idea also exist on the stable line ([v6.12.4 core-skills tree, 2026-10-14](https://github.com/bmad-code-org/BMAD-METHOD/tree/v6.12.4/src/core-skills)). For Claude, the `bmad-code-org/bmad-plugins` marketplace (created 2026-08-21, last commit 2026-09-05, no top-level `bin/`) carries a `bmad-toolbox` plugin with both skills ([bmad-plugins](https://github.com/bmad-code-org/bmad-plugins)). The README, however, tells users to install `bmad-core-tools`, a name the manifest doesn't use ([README](https://github.com/bmad-code-org/BMAD-METHOD) vs [marketplace.json](https://github.com/bmad-code-org/bmad-plugins/blob/main/.claude-plugin/marketplace.json), both read 2026-10-21). skills.sh shows **10,351 installs** for Deep Recon ([skills.sh API q=deep-recon, 2026-10-21](https://skills.sh/api/search?q=deep-recon)). Setup friction is current. Read-only `_bmad` files break repairs and updates on Windows ([issue #3124, 2026-10-19](https://github.com/bmad-code-org/BMAD-METHOD/issues/3124)), and a fixed regression had 16 skills bypassing the config resolver ([issue #3019, 2026-10-02](https://github.com/bmad-code-org/BMAD-METHOD/issues/3019)).

Outside BMAD, only the Draft half exists in any number, and nobody uses it. **rohankgeorge/the-researcher** comes closest. Its `deep-research-prompt-builder` turns a question into a brief framed like a consultant's engagement brief, for Claude Research, OpenAI Deep Research, Gemini Deep Research or Grok DeepSearch. It outputs only a `.md` prompt and explicitly does not run the research ([prompt-builder SKILL.md, 2026-07-20](https://github.com/rohankgeorge/the-researcher/blob/master/plugins/researcher/skills/deep-research-prompt-builder/SKILL.md)). Its sibling `research-verification` grades each claim-source pair in a returned report, checking that citations exist, trace back, haven't been retracted and reflect the latest position. That is the nearest standalone analogue to Process, but it returns verdicts, not a ledger later skills can read ([research-verification SKILL.md, 2026-07-20](https://github.com/rohankgeorge/the-researcher/blob/master/plugins/researcher/skills/research-verification/SKILL.md)). The repo is a Claude marketplace with no `bin/`, four skills and 2 stars. It has not been pushed to since its creation on 2026-07-20, and **the prompt builder shows 3 installs** ([the-researcher](https://github.com/rohankgeorge/the-researcher); [skills.sh API q=deep-research-prompt, 2026-10-21](https://skills.sh/api/search?q=deep-research-prompt)). The rest are smaller still. kj-aiml/deep-research-prompt pairs "GrillMe"-style questioning with prompt engineering (0 stars, 3 installs, [2026-05-23](https://github.com/kj-aiml/deep-research-prompt/blob/master/SKILL.md)). raymond-hear's Chinese-language builder targets Perplexity, OpenAI and Qwen (84 stars, 2 installs, non-spec frontmatter, [2026-02-10](https://github.com/raymond-hear/deep-research-prompt/blob/main/SKILL.md)). Four more `deep-research-prompt` skills show 1 to 3 installs each ([skills.sh API, 2026-10-21](https://skills.sh/api/search?q=deep-research-prompt)). Off-platform, gradually.ai's ChatGPT prompt generator added a Deep Research tab in its v4.0 release ([changelog, 2025-09-15](https://www.gradually.ai/chatgpt-prompt-generator/)). **None of the builders read has a Process step** that turns the returned report into structured evidence for a later skill.

The prevailing pattern runs the other way: idea validators run their research in-session. ailabs-393 `startup-validator` tells the agent to run at least 10 to 15 web searches ([SKILL.md, 2025-11-10](https://github.com/ailabs-393/ai-labs-claude-skills/blob/main/dist/skills/startup-validator/SKILL.md)). mathews-tom `idea-validator` starts three parallel WebSearch sub-agents ([SKILL.md, 2026-04-11](https://github.com/mathews-tom/armory/blob/main/skills/idea-validator/SKILL.md)). p2p2sp/viber adds a seven-member council to three research subagents ([SKILL.md, 2026-10-18](https://github.com/p2p2sp/viber/blob/main/viber/skills/idea-validator/SKILL.md)). c0x12c pre-allows WebSearch and WebFetch ([SKILL.md, 2026-03-30](https://github.com/c0x12c/ai-toolkit/blob/master/.codex/skills/idea-validation/SKILL.md)). lorkinsey's `ycofficehour` calls itself research-first ([SKILL.md, read 2026-10-21](https://github.com/Lorhard/lorkinsey/blob/main/plugins/ycofficehour/skills/ycofficehour/SKILL.md)). AojiLi's `idea-validator` asks for approval before its multi-agent fan-out and re-researches only the lanes a skeptic flags, but still does the research itself ([SKILL.md, 2026-07-13](https://github.com/AojiLi/startup-knowledge/blob/main/skills/idea-validator/SKILL.md)). Even the most-installed general research skill, mattpocock `research` (698,262 installs), runs a background agent that writes a cited Markdown file rather than briefing an outside tool ([research SKILL.md, read 2026-10-21](https://github.com/mattpocock/skills/blob/main/skills/engineering/research/SKILL.md); [skills.sh API q=research-brief](https://skills.sh/api/search?q=research-brief)). Its sibling `to-questionnaire` hands open questions to a human, not to a research tool ([to-questionnaire SKILL.md, read 2026-10-21](https://github.com/mattpocock/skills/blob/main/skills/productivity/to-questionnaire/SKILL.md)). haytham turned a startup idea into research, a GO/NO-GO verdict and an OpenSpec spec, but has been a personal tool since 2026-07 ([haytham README, 2026-07](https://github.com/arslan70/haytham)). The "delegate research, keep a ledger" design is therefore a minority position. That points to a gap, but it is also a sign that most authors think in-session research is good enough.

## Dozens of idea validators exist, and most fit claude.ai but default to harsh verdicts

Anthropic's docs set the bar for "installs into claude.ai chat." **Plugins work in web chat, the Desktop chat tab and Cowork once a paid user adds a GitHub marketplace under Customize > Plugins.** In chat, sub-agents and hooks are grayed out and local MCP servers don't run ([Use plugins in Claude, help center, undated](https://support.claude.com/en/articles/13837440-use-plugins-in-claude)). A top-level `bin/` blocks installation in claude.ai and Cowork entirely. A skills-only folder without `plugin.json` is listed for Claude Code only ([Plugin structure and testing, undated](https://claude.com/docs/plugins/build)). A single skill can be uploaded as a ZIP with `name` (≤64 characters) and `description` (≤1,024 characters), and the docs recommend keeping SKILL.md under 500 lines ([Create custom skills, undated](https://claude.com/docs/skills/how-to)). The open spec defines only `name`, `description`, `license`, `compatibility`, `metadata` (string-to-string) and experimental `allowed-tools` ([Agent Skills Specification, undated](https://agentskills.io/specification)). ## Matt Pocock's `grilling` is the default challenge target, with two catches

**`grilling` is the clear handoff target.** It maps a plan as a design tree. Each round it asks the open questions as a numbered list, with a recommended answer for each, worded so "yes" accepts the recommendation. It does not act until the user confirms they share an understanding ([grilling SKILL.md, first commit 2026-05-31](https://github.com/mattpocock/skills/blob/main/skills/productivity/grilling/SKILL.md)). Its frontmatter holds only `name` and `description`. The repo's ADR lists it as needing no setup ([ADR 0001, read 2026-10-21](https://github.com/mattpocock/skills/blob/main/.agents/adr/0001-explicit-setup-pointer-only-for-hard-dependencies.md)). It ships in the `mattpocock-skills` plugin (v1.3.1), whose repo is its own marketplace with no `bin/` ([plugin.json](https://github.com/mattpocock/skills/blob/main/.claude-plugin/plugin.json); [marketplace.json](https://github.com/mattpocock/skills/blob/main/.claude-plugin/marketplace.json), read 2026-10-21). That plugin is listed in both Anthropic's official and community marketplaces ([claude-plugins-official marketplace.json, read 2026-10-21](https://github.com/anthropics/claude-plugins-official/blob/main/.claude-plugin/marketplace.json)), so grilling passes both claude.ai tests. skills.sh counts **1,404,880 installs for `grill-me`, 1,203,092 for `grill-with-docs` and 960,166 for `grilling`** ([skills.sh API q=grill, 2026-10-21](https://skills.sh/api/search?q=grill)). The live page shows 963.4K and a first-seen date of 2026-06-04 ([skills.sh grilling](https://skills.sh/mattpocock/skills/grilling)). The pack also shows that handing off to it by name works. `grill-me` is now a manual-only alias whose whole body tells Claude to call the Skill tool with "grilling", and `grill-with-docs` calls `grilling` and `domain-modeling` ([grill-me](https://github.com/mattpocock/skills/blob/main/skills/productivity/grill-me/SKILL.md); [grill-with-docs](https://github.com/mattpocock/skills/blob/main/skills/engineering/grill-with-docs/SKILL.md), read 2026-10-21).

**The first catch is format.** Users complained that the batched-rounds redesign sends ten or more questions at a time. The request to bring back one-at-a-time grilling was closed as not planned on 2026-10-06 ([issue #831, opened 2026-08-10](https://github.com/mattpocock/skills/issues/831)). Hard caps on question count are out of scope, and so is routing questions through a harness's question UI, because the skills are meant to work in any harness ([question-limits.md](https://github.com/mattpocock/skills/blob/main/.out-of-scope/question-limits.md); [native-question-tool.md](https://github.com/mattpocock/skills/blob/main/.out-of-scope/native-question-tool.md), read 2026-10-21). **The second catch is surface.** Grilling sends a sub-agent to look up facts in the environment, and claude.ai chat does not run sub-agents ([grilling SKILL.md](https://github.com/mattpocock/skills/blob/main/skills/productivity/grilling/SKILL.md); [Use plugins in Claude](https://support.claude.com/en/articles/13837440-use-plugins-in-claude)). The maintainer also accepts no new skills and says workflows built from grilling belong in users' own prompts or in separate packs ([new-skills.md, read 2026-10-21](https://github.com/mattpocock/skills/blob/main/.out-of-scope/new-skills.md)). That is an explicit invitation for a pack that hands off to it.

The community marketplace's council and devil's-advocate plugins all have 0 stars ([community marketplace.json, read 2026-10-21](https://github.com/anthropics/claude-plugins-community/blob/main/.claude-plugin/marketplace.json)).

## No skill can start a research run; the user always presses the button

### claude.ai Research is a per-chat toggle with an undocumented report format

**No documented mechanism lets a skill turn Research on.** The user turns it on for each chat from the "+" menu, a blue indicator shows it is on, and web search must also be on. It is limited to Pro, Max, Team and Enterprise, on web, Desktop and Mobile ([Use research on Claude, help center, undated](https://support.claude.com/en/articles/11088861)). Research runs on Claude Opus 5.5, falling back to Opus 4.8, whatever model the chat has selected. It searches the web plus the chat's enabled connectors, calling connector tools without asking each time. It uses up usage limits faster than a normal chat. On Mobile it skips connectors, and it cannot use local MCP servers ([Use research on Claude](https://support.claude.com/en/articles/11088861); [Custom connectors, help center, undated](https://support.claude.com/en/articles/11175166)). The help article's troubleshooting tip is to ask Claude to use the research tool. That suggests that once the toggle is on, Research is a tool the model chooses to call, so a skill's wording could steer toward it. No Anthropic page confirms that a skill can do so.

**What a report contains is barely documented.** The current help article says nothing about format, citations, artifacts, run time or Projects ([Use research on Claude](https://support.claude.com/en/articles/11088861)). The launch post promised answers within minutes, with citations that are easy to check, back when Research was a US, Japan and Brazil beta for Max, Team and Enterprise; the current article supersedes those details ([Claude blog: Research, 2025-04-15](https://claude.com/blog/research)). The only first-hand description is a user report. It says Deep Research reports appear in the "Your creations" artifacts sidebar and download as `.md` files with generic `artifact-<hash>.md` names. One "Code Execution and File Creation" toggle controls research processing, file generation and artifacts together. Project files are read-only to Claude and sit in a flat list ([anthropics/claude-code#28161, 2026-02-24, closed by a bot 2026-03-24](https://github.com/anthropics/claude-code/issues/28161)). **There is no documented "save to Project" action.** Project knowledge is added by the user uploading files with "+" ([How can I create and manage projects?, help center, undated](https://support.claude.com/en/articles/9519177-how-can-i-create-and-manage-projects)). So getting a report into project knowledge today means downloading it and uploading it again. The redesigned Projects do gather added files and Claude's artifacts into a library, but only in a Claude Code beta, and nothing says that covers Research reports ([Projects redesigned, 2026-09-17](https://claude.com/resources/articles/projects-redesigned)). A third-party guide says there is no `/research` command or API. It works around this by having `claude --chrome` click the toggle and poll for 5 to 30 minutes, then save Markdown under `./docs/research/` ([DEV Community, Bilal Haidar, posted Jan 27, year likely 2026](https://dev.to/bhaidar/how-to-use-claudeais-research-toggle-inside-claude-code-469d)).

### Claude Code's `/deep-research` takes one question and answers in the session

**`/deep-research <question>` takes free text, not a structured brief.** It is a bundled dynamic workflow. It fans web searches out across several angles, fetches and cross-checks sources, votes on each claim, and returns a cited report with failed claims removed. It needs the WebSearch tool ([Dynamic workflows, undated](https://code.claude.com/docs/en/workflows)). **Since v2.1.218 only the user can start it**; before that, Claude could start it too ([Commands, undated](https://code.claude.com/docs/en/commands)). An approval prompt lists the planned phases. Auto mode asks only on first launch, manual mode asks every time, and `-p` and the SDK need `Workflow` allow rules. Nobody can give input mid-run. **The finished report lands in the session transcript** with per-claim citations, and claims the verifiers couldn't check are marked unverified rather than refuted. The only file written is the orchestration script, under `~/.claude/projects/`; the docs describe no report file ([Dynamic workflows, undated](https://code.claude.com/docs/en/workflows)). Cost is explicit. A run can use meaningfully more tokens than doing the work in conversation. A "Large workflow" warning appears above 25 agents or a projected 1.5M tokens. The default size is under 10 agents (under 5 on Pro from v2.1.271). Pro users must turn workflows on in `/config`, and admins can turn them off ([Dynamic workflows](https://code.claude.com/docs/en/workflows)). Only saved, user-written workflows take structured `args`.

The **`anthropic-skills:deep-research` skill** is a different tool, and its report format is the one this report follows. It takes a natural-language request. It briefs each researcher with fixed fields (Objective, Key questions, Suggested sources, Constraints, save path). Notes go to `{cwd}/research_notes/{title}/` and the report to `{cwd}/reports/{title}.md`. It allows at most one extra research round, to avoid timeouts. It runs only where an Agent or Task tool can spawn subagents, which rules out plain claude.ai chat ([deep-research SKILL.md, local copy modified 2026-10-09](file:///Users/ramboz/.claude/local-agent-mode-sessions/skills-plugin/55ffbe58-9102-4be8-be99-6089bbad141c/2468e27a-1eff-46c8-8f73-8381c17f877d/skills/deep-research/SKILL.md)). Its reports are a title, a BLUF paragraph, 3 to 5 narrative sections with inline `([Source](URL))` citations, and a conclusion ([report-writer.md, 2026-10-09](file:///Users/ramboz/.claude/local-agent-mode-sessions/skills-plugin/55ffbe58-9102-4be8-be99-6089bbad141c/2468e27a-1eff-46c8-8f73-8381c17f877d/skills/deep-research/references/report-writer.md)). Its researcher notes use fixed per-question sections (Takeaway, Cited Findings, Inferences, Gaps) ([researcher.md, 2026-10-09](file:///Users/ramboz/.claude/local-agent-mode-sessions/skills-plugin/55ffbe58-9102-4be8-be99-6089bbad141c/2468e27a-1eff-46c8-8f73-8381c17f877d/skills/deep-research/references/researcher.md)). Its frontmatter doesn't block model invocation, so another skill could in principle defer to it. A triage brief that mirrors its four fields could be reused unchanged.

## Skill handoffs are soft suggestions, and chat Projects still cannot push to GitHub

### One skill can name another, but nothing guarantees it returns

**No Anthropic doc defines a way for one skill to call another, on any surface.** The overview promises that skills can be combined for multistep tasks ([Agent Skills overview, undated](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview)), and the launch post says skills stack together, with no mechanism given ([Introducing Claude Skills, 2025-10-16, updated 2025-12-18](https://claude.com/blog/skills)). Claude Code documents only user-side composition. A user can stack `/write-tests /fix-issue 123` at the prompt (only the first loads through `-p` or the SDK), or chain up to six skills at the start of a message. A skill named mid-message counts as permission to run it. `disable-model-invocation: true` blocks Claude from calling a skill and removes its description from context ([Extend Claude with skills, undated](https://code.claude.com/docs/en/skills); [Commands, undated](https://code.claude.com/docs/en/commands)). In practice nested `Skill()` calls happen, and they break in two documented ways. **When a skill calls another, control returns to the main session rather than to the parent, and the parent's workflow stops.** This happens with and without `context: fork`, has been reproduced from v2.1.3 to v2.1.37, and has had no Anthropic response. A posted workaround, reading the child's SKILL.md inline, failed again in production four days later ([anthropics/claude-code#17351, opened 2026-01-10, open](https://github.com/anthropics/claude-code/issues/17351)). Separately, `disable-model-invocation` blocks a parent skill's call as well as proactive routing, so a child cannot be callable by its parent yet hidden from automatic selection. Telemetry already distinguishes `nested-skill` calls, but staff have not replied ([anthropics/claude-code#86763, opened 2026-08-14, open](https://github.com/anthropics/claude-code/issues/86763)).

In claude.ai, Claude decides when a skill is needed. The only lever the help center gives is naming the skill in the request. It says nothing about skills combining ([Using Skills in Claude, help center, undated](https://support.claude.com/en/articles/12512180-using-skills-in-claude)). **Selection itself is unreliable at scale.** Claude Code keeps every skill name in its listing, but drops descriptions once they exceed 1% of the context window, least-invoked first. Each entry is capped at 1,536 characters, and after compaction only the first 5,000 tokens of each invoked skill are re-attached ([Extend Claude with skills](https://code.claude.com/docs/en/skills)). Anthropic's authoring guide warns that 100 or more skills may compete, and says to test on Haiku, Sonnet and Opus ([Skill authoring best practices, undated](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)). The only measured activation rate found is third-party: 55% and 50% baseline on Sonnet 4.5 across 22 prompts, and 100% with a forced-evaluation hook ([Scott Spence, 2026-02-08](https://scottspence.com/posts/measuring-claude-code-skill-activation-with-sandboxed-evals)). One 2026 change helps a two-surface pack. **Skills enabled on claude.ai now sync one way into Claude Code (v2.1.273+)** for the same signed-in account, into `~/.claude/skills/synced/`, about every 10 minutes ([Using Skills in Claude](https://support.claude.com/en/articles/12512180-using-skills-in-claude); [Extend Claude with skills](https://code.claude.com/docs/en/skills)). The platform overview still says custom skills don't sync across surfaces, and it disagrees with the support article on whether the Free plan gets skills ([Agent Skills overview](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview)).

### The only Project-to-pull-request path in 2026 is a Claude Code beta

**As of October 2026, no first-party path moves files from a claude.ai chat Project into a GitHub repo.** The GitHub integration reads only, from repo to Project. It reads file names, contents and branch content, but not commit history, PRs or issues. It works only in private projects, refreshes with "Sync now", and points to Claude Code for editing code or opening PRs ([GitHub integration, claude.com docs, undated](https://claude.com/docs/connectors/github); [Use the GitHub integration, help center, updated about 2026-10-20](https://support.claude.com/en/articles/10167454-use-the-github-integration)). The account export covers conversations and user data and says nothing about projects ([Export your Claude data, undated](https://support.claude.com/en/articles/9450526)). A June 2025 request to connect Claude Code to claude.ai Projects is still open with no staff reply; its workarounds are copy-paste and `.md` copies kept in the repo ([anthropics/claude-code#2511, 2025-06-24](https://github.com/anthropics/claude-code/issues/2511)). **The real 2026 change is the Projects redesign.** In it, a coordinator hands work to worker threads, each a Claude Code cloud session on its own branch that can open PRs and run tests. But it shipped on 2026-09-17 as a Claude Code beta for select Pro and Max users who have no existing web or desktop projects. Team and Enterprise come later. Existing chat Projects carry on unchanged until an undated upgrade, and the page describes no migration or export ([Projects redesigned, 2026-09-17](https://claude.com/resources/articles/projects-redesigned)). The users most likely to start in a chat Project are therefore last in line. A custom remote-MCP connector to GitHub's official server might let chat write to a repo. Custom connectors can modify data, and GitHub's server has a `create_pull_request` tool needing `repo` scope, with Claude Desktop listed as a host ([Custom connectors, undated](https://support.claude.com/en/articles/11175166); [github-mcp-server README, undated](https://github.com/github/github-mcp-server)). Whether its OAuth works through claude.ai's connector flow was not verified.

## Lean packs win on selection quality, but reach follows authors and official listings

### The cost of bloat is measured; the preference for small packs is mostly stated

**The best evidence on bloat is a controlled study.** Databricks researchers tested Haiku 4.5 and Sonnet 4.6 across 2,545 trajectories. Pass rates fell by 0.08, 0.14 and 0.21 as the skill library grew to 52, 102 and 202 skills, compared with a library holding only the helpful skills. Runs that used only the correct skills dropped from 88.0% to 52.6%, and runs that used no skill at all rose from 12.0% to 38.5% ([More Skills, Worse Agents?, arXiv 2605.24050 v2, 2026-06-23](https://arxiv.org/html/2605.24050)). About two-thirds of the drop came from skills shadowing one another. Pure context overhead was not statistically distinguishable from zero. So the harm comes from wrong choices, not raw token cost, which matters for a pack designed to defer to other skills by description. SkillsBench found that curated skills raised pass rates from 33.9% to 50.5%, and that focused skills with at most three internal modules beat larger bundles ([SkillsBench, arXiv 2602.12670, v4 2026-06-14](https://arxiv.org/abs/2602.12670)). Anthropic's docs confirm the always-on cost. Every enabled plugin's skill descriptions count against usage on every turn. `claude plugin details` reports an "Always-on" token figure. The fix the docs suggest is to split large plugins, while warning that shorter descriptions can stop skills triggering. Only official-marketplace plugins show a context-cost estimate before install ([Measure plugin cost and usage, undated](https://code.claude.com/docs/en/plugins/measure)). Users hit the listing budget in practice. One report counted 81 descriptions dropped ([#68134, 2026-06-13](https://github.com/anthropics/claude-code/issues/68134)). Another found only 9 of 36 project skills kept their descriptions, apparently filled alphabetically, which contradicts the docs' least-invoked-first rule ([#81081, 2026-07-25, open](https://github.com/anthropics/claude-code/issues/81081)). A 25-skill project overflowed the roughly 8,000-character budget, and Claude then wrote its own scripts instead of using the skills ([#64606, 2026-06-02](https://github.com/anthropics/claude-code/issues/64606)). A 163-skill fleet ran 34% over budget, with a mean description of 740 characters against about 176 in Anthropic's examples ([melodic-software #3505, 2026-08-31](https://github.com/melodic-software/claude-code-plugins/issues/3505)).

**Preference for small packs is stated, not surveyed.** Matt Pocock positions their skills as small, easy to adapt and composable, against GSD, BMAD and Spec Kit, which they say take control of the process away from the user ([mattpocock/skills README, undated, read 2026-10-21](https://github.com/mattpocock/skills)). Thoughtworks' Birgitta Böckeler found Spec Kit generated repetitive, verbose files (about eight for one spec) and was overkill for a small feature ([martinfowler.com, 2025-10-15](https://martinfowler.com/articles/exploring-gen-ai/sdd-3-tools.html)). Addy Osmani argues for small, phase-loaded skills: about 11 for a complex feature, about 3 for a bug fix ([Agent Skills, 2026-05-03](https://addyosmani.com/blog/agent-skills/)). Superpowers draws specific complaints. Its SessionStart hook injects emphatic must-invoke wording into every session, which makes models invoke skills before trivial questions ([obra/superpowers#2454, 2026-10-03](https://github.com/obra/superpowers/issues/2454)). An HN commenter called its skills bloat that degrades capable models ([HN, 2026-08-13](https://news.ycombinator.com/item?id=49283567)). Other HN users describe hiding a team's bloated skills directory ([2026-10-05](https://news.ycombinator.com/item?id=49969899)) and removing skills that mostly inflated tokens ([2026-08-04](https://news.ycombinator.com/item?id=49170484)). Some counter that progressive disclosure already makes skills cheaper than MCP tool definitions ([2026-08-05](https://news.ycombinator.com/item?id=49179362)). Packs also collide. Two packs both ship `/handoff`, and the installer wouldn't say which one runs ([infragate/capa#330, 2026-10-15](https://github.com/infragate/capa/issues/330)). Claude Code's listing doesn't show where a skill came from, so the model treated a bundled skill as user-authored ([#93318, 2026-09-10](https://github.com/anthropics/claude-code/issues/93318)). **The useful distinction is not skill count.** Matt Pocock's pack has 55 skills on skills.sh against Superpowers' 15. What separates them is whether a pack injects an always-on bootstrap or leaves standalone skills for the user to call ([skills.sh/mattpocock/skills](https://skills.sh/mattpocock/skills); [skills.sh/obra/superpowers](https://skills.sh/obra/superpowers)).

### Discovery requires a marketplace add, and installs concentrate hard

**Third-party packs install the same way on both surfaces: the user adds a GitHub marketplace by hand.** Claude Code pre-registers only `claude-plugins-official`. Anything else needs `/plugin marketplace add owner/repo`, or one-step `/plugin install <name> --marketplace owner/repo` from v2.1.275. The Discover tab shows nothing from a marketplace until it is added. Auto-update is off by default for community and third-party marketplaces. Cloud sessions on claude.ai/code have no plugin browser ([Install and manage plugins, undated](https://code.claude.com/docs/en/discover-plugins)). In claude.ai the path is Customize > Plugins > Add marketplace (GitHub, GitLab or Bitbucket) or Upload. Directory plugins appear on Pro, Max, Team and Enterprise. Anthropic reviews directory listings but not plugins added by URL. claude.ai installs sync into Claude Code as `<name>@synced`, but not the other way ([Plugins, claude.com docs, undated](https://claude.com/docs/plugins/overview)). Managed organizations can block all of this. Owners can hide sources or allowlist marketplaces, and since 2026-10-02 Enterprise members' plugins default to "Requires review" ([Manage plugins for your organization, undated](https://claude.com/docs/plugins/admin); [Claude Code org plugins, undated](https://code.claude.com/docs/en/plugins/org)). Authors fly blind. Claude Code reports no usage back to them, and OpenTelemetry redacts third-party plugin names by default ([Measure plugin cost and usage](https://code.claude.com/docs/en/plugins/measure)). Some packs skip the plugin system entirely. gstack installs by git clone plus a Bun-based `./setup`, and Spec Kit through `uv tool install` ([gstack README](https://github.com/garrytan/gstack); [spec-kit README](https://github.com/github/spec-kit), read 2026-10-21).

**Install numbers are concentrated, and which pack wins depends on the channel.** Vercel reports that skills.sh reached 1 million skills in 7 months with nearly 280 million installs. **Nearly half of all skills were installed exactly once, and the top 375 (0.04%) take 62% of installs.** Vercel itself warns these are aggregate counters, not unique people ([State of agent skills, 2026-09-25](https://vercel.com/blog/state-of-agent-skills)). A critic notes that Vercel runs the registry it is measuring ([apis.io, 2026-10-08](https://apis.io/2026/10/08/vercel-counts-a-million-skills-and-publishes-none-for-its-own-api/)). On skills.sh, small single-purpose skills lead. mattpocock/skills holds 13 of the top 30 slots and 29.4M installs across 55 skills. Superpowers' top skill has 400.8K. gstack totals only 44.3K across 67 skills, mostly because it installs by git clone ([skills.sh](https://skills.sh); [skills.sh/garrytan/gstack](https://skills.sh/garrytan/gstack), 2026-10-21). On Anthropic's marketplace the picture flips. **Superpowers has 1,009,371 installs, next to Anthropic's Frontend Design at 1,134,112, while Matt Pocock's plugin has 1,745** ([claude.com/plugins/superpowers](https://claude.com/plugins/superpowers); [frontend-design](https://claude.com/plugins/frontend-design); [mattpocock-skills](https://claude.com/plugins/mattpocock-skills), 2026-10-21). Where a pack installs as a single unit, frameworks do at least as well. Small packs comparable to this idea sit far lower. Deep Recon has 10,351 installs, strategy-red-team 9,163, slavingia 2,966, builder-os 1,691, lenny 514, vibe-check 158 (despite 623 stars) and the-researcher 3 (sources in the tables above). Bundling inflates per-skill counts: one bundle install counts once for every skill in it ([Skillselion, 2026-07-29](https://dev.to/skillselion/the-entire-claude-code-skills-top-10-belongs-to-three-authors-anthropic-holds-one-slot-27jc)). Reach follows audience. Jesse Vincent's Superpowers essay drew 435 HN points, while direct repo submissions drew 1 to 4. gstack's launch drew 15 points despite 137K stars ([HN Algolia "superpowers"](https://hn.algolia.com/api/v1/search?query=superpowers&tags=story); [HN Algolia "gstack"](https://hn.algolia.com/api/v1/search?query=gstack&tags=story)). Single-purpose skill Show HNs scored 76 to 363 points ([HN Algolia "claude skills"](https://hn.algolia.com/api/v1/search?query=claude%20skills&tags=story); [HN Algolia "agent skills"](https://hn.algolia.com/api/v1/search?query=agent%20skills&tags=story)). Matt Pocock's README points readers to a newsletter of about 60,000 developers ([mattpocock/skills README](https://github.com/mattpocock/skills)).

## Neither target tool exists; here is what comes closest and how it was searched

**(a) No lean idea-triage pack delegates research to the user's research tools and hands off to build tools.** The capability exists inside BMAD: Deep Recon for Draft and Process, Forge Idea for challenge, and routing on to a product brief, PRD or `bmad-build` ([Explore and Validate an Idea](https://github.com/bmad-code-org/BMAD-METHOD/blob/main/docs/plan/explore-and-validate-an-idea.md); [Research a Decision](https://docs.bmad-method.org/plan/research-a-decision/), read 2026-10-21). ## Conclusion

The idea's novelty is not its loop, which BMAD shipped two months ago, but where it can run. Every boundary the pack crosses is a hand-off to the user: starting Research or `/deep-research`, saving a report into a Project, deferring to grilling, moving files to a repo. So the pack's real design work is in paste-ready artifacts: one brief that fits the deep-research skill's four fields and also fits on a single `/deep-research` line, one ledger file with a stated target path, and the grilling suggestion placed last, so a broken nested call (#17351) costs nothing. Deep Recon's claim schema and research firewall are the bar a lean ledger has to meet or beat, and Deep Recon's dependence on `uv` and a V7 alpha is the opening. That opening could close if BMAD slims its toolbox plugin. The bloat evidence works in the pack's favor, but only on one condition. The study blames mis-selection, not token cost, so a pack that defers to other skills by description is exposed exactly where its descriptions are weakest: new and rarely invoked, the first to be dropped.

Two findings cut against the idea and need deliberate answers. The field's near-unanimous anti-sycophancy stance means "encouraging by default" must be argued as a choice for the moment before the user has committed, the way gstack's Builder mode does, not as a softer verdict. And distribution, not design, decides reach. Half of skills are installed once, authors get no usage data, and the official directory or an existing audience separates Superpowers' million installs from the-researcher's three. Getting listed in the official directory, or riding grilling's audience by being the pack that hands off to it, is the most realistic path to reach.
