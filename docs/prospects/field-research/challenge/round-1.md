## Rival: how would an incumbent respond?

_Playing: GitHub, as maintainer of Spec Kit and its first-party `assess`
extension (`LND-15`, `LND-32`)._

_How I would respond if this got traction (judgment):_ At first I would
ignore it. A pegboard plugin is one of hundreds of idea-validation repos
(`LND-14`), and my community catalog already holds 182 extensions (`V-07`). If
it grew, I would not need to copy it. My tooling can already wrap any
`SKILL.md` as a Spec Kit extension (`V-08`), and `assess` invites richer
pre-spec flows to feed into it (`V-02`). I would copy only the cheap parts, a
money row in the scorecard and softer wording, and I could ship them within a
week or two: I put out 12 releases in the last four weeks (`V-06`). I would not
undercut on price, because I am already free and MIT (`MON-07`).

### What holds up

- **The dossier reads me accurately.** `LND-15` and `LND-32` match my README
  and command files (`V-02`). On the cheap parts, "what stops an incumbent:
  nothing much" is the honest answer. Ranking me first in the register, as
  R-01, is the right call.
- **What I could not easily copy:**
  - **A chat Project before any repo exists.** `assess` runs inside an
    initialized Spec Kit project, and setup needs Python 3.11+, uv and a
    coding agent (`V-02`). So far, my only move off the terminal is a
    workflow on my own repo that runs `assess` from a labelled issue
    (`V-03`). That still needs a repository, not a claude.ai chat. The skills
    I generate for Claude carry frontmatter keys that only Claude Code
    accepts (`V-05`), and claude.ai uploads reject those keys (`ENB-11`), so my
    generated skills do not carry over to chat. I also have no reason to build
    for another vendor's chat app.
  - **Market research on the open web.** My research stage fetches freely
    only from code and docs hosts. It skips other hosts in automated runs,
    and I list that as a security guardrail (`LND-32`, `V-02`). The pricing
    pages, Show HN threads and vendor sites behind `DEM-27`, `MON-01` to
    `MON-05` and `RCH-04` are off my default path. Widening the allowlist
    would be a security-policy decision at GitHub, not a quick pull request.
  - **Encouragement as an identity.** My README calls `assess` a funnel: most
    ideas should stop or be parked before shaping, and a documented stop counts
    as success (`V-02`). I can soften what I do in practice, and I already have
    (`V-04`). But if I marketed encouragement, I would contradict my own design
    statement. As an identity, the posture holds up. As a feature, it can be
    copied (concern 1).
  - **A money lens that starts from the builder's own constraints**, and
    accepts "none, by choice" as a complete answer. My scorecard is
    role-neutral and shaped for organizations: it scores strategic fit, and
    value against the cost of doing nothing (`LND-32`). Adding a revenue row
    would be cheap for me. A lens that starts from what one builder refuses
    does not fit a role-neutral funnel.
  - **The family handoff and the author's own record** (`OWN-01` to
    `OWN-05`). I would not copy these. The airlock story is also the kind of
    essay that spreads where links to a repo do not (`RCH-04`).
- **Good, though copyable:** the ledger has five provenance tags, every
  absence lists its searches, and there is a link check (176 of 178 links
  resolve). I have `ASSUMPTION` tags and a required "evidence against"
  section, but no link check, and I could add one in a release. For now, it
  is a difference you can demonstrate.
- **Where I am weakest today, from your side:** setup needs a terminal,
  research is limited to an allowlist, there is no money criterion, the
  framing starts from a verdict, and the artifacts live in a repository
  (`V-02`, `V-06`).
